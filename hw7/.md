# 排列組合 $C(n, k)$ 計算：動態規劃 vs 非動態規劃

本專案旨在探討排列組合中組合數 $C(n, k)$（即從 $n$ 個相異物件中取出 $k$ 個的組合數）的計算方法，比較 **動態規劃（Dynamic Programming）** 與 **非動態規劃（純遞迴與數學公式）** 的原理、複雜度與效能差異。

---

## 核心數學原理

$C(n, k)$ 的遞迴關係建立在巴斯卡三角形（Pascal's Triangle）上：

$$C(n, k) = C(n-1, k-1) + C(n-1, k)$$

**邊界條件（Base Cases）：**
* 當 $k = 0$ 或 $k = n$ 時，$C(n, k) = 1$
* 當 $k > n$ 或 $k < 0$ 時，$C(n, k) = 0$

---

## 程式碼實作 (Python)

以下提供包含詳細註解與說明的完整 Python 程式碼，展示三種不同解法：

```python
"""
===============================================================================
題目：排列組合 C(n, k) 計算
說明：比較 Dynamic Programming (DP) 與 Non-DP 方法的差異與複雜度
===============================================================================
"""

# -----------------------------------------------------------------------------
# 1. 動態規劃法 (Dynamic Programming, Bottom-Up)
# -----------------------------------------------------------------------------
def combination_dp(n: int, k: int) -> int:
    """
    【原理說明】
    使用動態規劃（由底而上建表）將問題拆解為「重疊子問題」。
    利用巴斯卡三角形公式：C(n, k) = C(n-1, k-1) + C(n-1, k)
    為了節省空間，我們使用一維陣列並由後往前更新，避免覆蓋上一輪所需的舊狀態。

    【複雜度分析】
    - 時間複雜度：O(n * k) - 需要雙層迴圈計算表中的數值。
    - 空間複雜度：O(k)     - 空間優化後，只需長度為 k+1 的一維陣列。
    """
    if k < 0 or k > n:
        return 0
    if k == 0 or k == n:
        return 1

    # 利用對稱性 C(n, k) == C(n, n-k) 減少計算量
    k = min(k, n - k)

    # dp[j] 表示當前第 i 層的 C(i, j) 數值
    dp = [0] * (k + 1)
    dp[0] = 1  # 邊界條件：C(i, 0) = 1

    for i in range(1, n + 1):
        # 倒序更新，確保計算 dp[j] 時用的 dp[j-1] 是來自上一層 (i-1) 的舊值
        for j in range(min(i, k), 0, -1):
            dp[j] = dp[j] + dp[j - 1]

    return dp[k]


# -----------------------------------------------------------------------------
# 2-1. 非動態規劃 - 純遞迴法 (Naive Recursion)
# -----------------------------------------------------------------------------
def combination_recursive(n: int, k: int) -> int:
    """
    【原理說明】
    直接依照數學遞迴定義求解。每次呼叫都會將問題拆成兩個子問題：
    "包含第 n 個元素" (C(n-1, k-1)) + "不包含第 n 個元素" (C(n-1, k))。
    此方法沒有儲存已算過的狀態，導致大量重疊問題被重複計算。

    【複雜度分析】
    - 時間複雜度：O(2^n) - 遞迴樹的節點數呈指數級成長。
    - 空間複雜度：O(n)   - 主要為遞迴呼叫堆疊（Recursion Stack）的深度。
    """
    if k < 0 or k > n:
        return 0
    if k == 0 or k == n:
        return 1

    return combination_recursive(n - 1, k - 1) + combination_recursive(n - 1, k)


# -----------------------------------------------------------------------------
# 2-2. 非動態規劃 - 數學公式連乘除法 (Direct Multiplication)
# -----------------------------------------------------------------------------
def combination_math(n: int, k: int) -> int:
    """
    【原理說明】
    直接運用數學階乘簡化公式：
    C(n, k) = (n * (n-1) * ... * (n-k+1)) / (1 * 2 * ... * k)
    採用邊乘邊除的策略，確保中間計算結果不會產生不必要的浮點數誤差。

    【複雜度分析】
    - 時間複雜度：O(k) - 只需要進行 k 次乘法與除法。
    - 空間複雜度：O(1) - 僅需常數等級的變數空間。
    """
    if k < 0 or k > n:
        return 0
    if k == 0 or k == n:
        return 1

    k = min(k, n - k)
    result = 1
    for i in range(1, k + 1):
        result = result * (n - i + 1) // i

    return result


# -----------------------------------------------------------------------------
# 主程式測試
# -----------------------------------------------------------------------------
if __name__ == "__main__":
    n, k = 30, 10
    
    print(f"=== 計算 C({n}, {k}) ===")
    print(f"1. 動態規劃 (DP) 計算結果          : {combination_dp(n, k)}")
    print(f"2. 數學公式法 (Math) 計算結果       : {combination_math(n, k)}")
    
    # 提醒：純遞迴在 n 稍微變大時會極為緩慢，故測試小數值
    small_n, small_k = 10, 4
    print(f"\n=== 計算 C({small_n}, {small_k}) ===")
    print(f"3. 純遞迴法 (Recursive) 計算結果    : {combination_recursive(small_n, small_k)}")
```

## 原理、複雜度與詳細比較

| 比較項目 | 動態規劃 (DP) | 非動態規劃：純遞迴 | 非動態規劃：數學公式法 |
| :--- | :--- | :--- | :--- |
| **求解邏輯** | 由底而上（Bottom-Up），記錄中間狀態，避免重複計算。 | 由上而下（Top-Down），依照定義將問題分裂，大量重複計算。 | 直接利用組合數學展開式進行連乘連除。 |
| **時間複雜度** | $\mathcal{O}(n \times k)$ | $\mathcal{O}(2^n)$ （指數級，極慢） | $\mathcal{O}(k)$ （線性，極快） |
| **空間複雜度** | $\mathcal{O}(k)$ （一維陣列優化） | $\mathcal{O}(n)$ （呼叫堆疊深度） | $\mathcal{O}(1)$ （常數空間） |
| **優點** | 避免重複計算，適合用於擴充至需連續查詢多組 $C(i, j)$ 的情境。 | 程式碼簡潔，完全忠實反映數學定義。 | 時間與空間效率皆達到最優。 |
| **缺點** | 需要額外陣列空間維護 DP 狀態。 | $n > 30$ 時即會因計算量過大而卡死或溢位。 | 若程式語言不支援大數運算，中間乘積容易造成整數溢位（Python 已無此限制）。 |
