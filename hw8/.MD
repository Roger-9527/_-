# 旅行推銷員問題 (TSP) - 五種演算法比較

本專案使用 Python 實作了五種不同的演算法來解旅行推銷員問題 (Traveling Salesperson Problem, TSP)，並確保所有演算法皆使用**同一組隨機生成的城市座標與初始路徑**進行測試。程式會透過 `matplotlib` 產生 1x5 的並排圖表，直觀顯示各演算法的收斂結果與最短距離。

## 測試數據設計
- **城市數量**：20 個城市
- **座標範圍**：於 $100 \times 100$ 的 2D 歐幾里得平面上隨機生成。
- **初始狀態**：除了貪婪演算法自行建構路徑外，其餘四種優化演算法皆輸入同一個隨機生成的初始路徑 (Initial Tour)，確保比較基準一致。

## 演算法原理說明

### 1. 改良法 (Improvement Method - 2-Opt)
- **原理**：2-Opt 是一種局部搜尋法。旅行推銷員問題的次優解中，最常見的瑕疵是「路線交叉」。改良法透過選擇路徑中的兩個節點，將兩節點之間的路徑順序反轉（等同於打斷兩條邊並重新連接）。若反轉後總距離減少，則保留該變更。
- **特性**：能快速解開交叉路徑，非常適合用於平滑化其他演算法產生的初步解。

### 2. 爬山演算法 (Hill Climbing)
- **原理**：屬於局部搜尋演算法。程式每次在當前路徑中「隨機」挑選兩個城市進行位置交換（產生一個鄰居解）。如果新解的距離比當前距離短（上坡），就立刻移動到該新解；若較差則捨棄。
- **特性**：計算速度極快，但非常容易陷入「局部最佳解 (Local Optima)」，無法跳出目前的低谷來尋找全局最佳解。

### 3. 模擬退火法 (Simulated Annealing)
- **原理**：靈感來自金屬冶煉的退火過程。與爬山演算法類似，會隨機產生鄰居解。但核心差異在於：即使新解比當前解差，它仍有一定機率 $P = e^{-\Delta E / T}$ 接受這個較差的解。隨著時間推進，系統溫度 $T$ 會逐漸下降（冷卻）。
- **特性**：高溫時允許大量隨機探索（跳出局部最佳），低溫時則轉變成類似爬山演算法的收斂模式，通常能找到比爬山法更優的全局解。

### 4. 梯度下降法 (Discrete Steepest Descent)
- **原理**：標準的梯度下降法需要計算連續函數的導數，並不直接適用於 TSP 這樣的離散排列問題。因此，在此實作離散版本的「最陡下降法 (Steepest Descent)」。有別於爬山法隨機找到一個好解就移動，梯度下降法會**完整評估當前狀態下所有的相鄰解**（所有可能的兩兩交換），計算每一條移動路徑的「梯度（成本下降量）」，並選擇下降幅度最大（最陡）的鄰居進行移動。
- **特性**：每一步的計算成本較高，但保證每次移動都是當前局部空間中最優的方向。當周圍沒有任何解可以讓成本下降時，演算法即停止（抵達梯度為0的鞍點或局部最底）。

### 5. 貪婪演算法 (Greedy Algorithm / Nearest Neighbor)
- **原理**：不依賴初始完整路徑，而是從一個隨機起點城市開始，每一步都尋找距離當前城市「最近且尚未拜訪過」的城市作為下一站，直到所有城市走完，最後再連回起點。
- **特性**：建構速度最快，因為它只看眼前的最佳選擇（短視近利）。缺點是通常在最後幾步會被迫連接距離極遠的剩餘城市，導致最終總距離並非最佳。
